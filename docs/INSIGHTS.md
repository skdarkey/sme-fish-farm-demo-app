# Advanced insights and the farm chatbot

**Advanced insights** is manager-only. Choose local daily records or pond water visits; select ponds, dates, a metric and daily/weekly/monthly
aggregation. Feed, deaths and harvest are summed only for local daily logs. Water
metrics and sample weights use observation-weighted means. Weekly buckets begin
Monday. Morning/evening are separate series for water visits.

Local farm data also offers estimated biomass, fish remaining, survival and FCR
as period-end snapshots per batch. Snapshot dates are capped at the selected end;
sample dates show the age of the growth evidence. These are cumulative stock/ratio
KPIs, not sums or means of daily KPI values.

The table includes observation counts, the last two observed periods and their
absolute change. A linear slope per day is shown only with at least three periods.
Missing periods stay blank; none are interpolated. The slope is descriptive, not a
forecast. Sampling composition can affect trends. Financial results and causal
effects are not inferred from these data.

## Connect an LLM

The app connects to a separately running model server. It does not download model
weights or assume the workstation has enough memory/GPU capacity for a particular
model. Select a model suitable for your machine and install it in your inference
server. The chatbot remains disabled until `LLM_MODEL` is configured.

For local [Ollama](https://docs.ollama.com/api/chat), start Ollama, install your
chosen model, then set in `.env`:

```dotenv
LLM_PROVIDER=ollama
LLM_BASE_URL=http://127.0.0.1:11434
LLM_MODEL=YOUR_INSTALLED_MODEL
```

For an OpenAI-compatible chat-completions server:

```dotenv
LLM_PROVIDER=compatible
LLM_BASE_URL=https://YOUR_MODEL_HOST/v1
LLM_MODEL=YOUR_DEPLOYED_MODEL
LLM_API_KEY=YOUR_PRIVATE_KEY
```

Restart Streamlit after changing environment settings. HTTP is accepted only for
loopback endpoints; remote endpoints require HTTPS. Endpoint/model configuration
is controlled by the server operator, not by chat messages. The selected endpoint
and model appear above the chat. Questions and the displayed evidence are sent to
that endpoint when submitted. No remote endpoint is configured by default.

## Evidence and boundaries

Expand **Evidence supplied to the model** to inspect the exact numerical context.
It includes scope, observation counts, summary statistics, trend results and,
for daily farm data, cumulative batch KPIs as of the end date. These cumulative
KPIs can include records before the trend start; their basis is labeled explicitly.
The packet bounds detailed listings to the first 20 batches, first 30 pond names
and last 36 period rows; aggregate counts/totals still use the complete filtered set.

Staff identities, field notes, OIDC claims, secrets and user-access records are
excluded. Farm labels are treated as untrusted data. The assistant is instructed
to cite packet sections and acknowledge missing evidence. This is structured
context retrieval, not a model trained on farm data and not an arbitrary SQL agent.
The model cannot browse, run code, write records or manage users.

History is confined to the current Streamlit session and current identity/data
scope. Changing filters, data, model or identity clears it. Requests use a bounded
history and timeout, with useful error messages if inference is unavailable.
No fallback answer pretends to be generated by an LLM. Generated answers may still
be wrong; review numeric claims against the visible evidence.

## Recommended self-hosted model

Start with [Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B), licensed
Apache 2.0, through [Ollama](https://ollama.com/library/qwen3.5).
The Ollama 9B download is about 6.6 GB; runtime memory also includes context
and concurrency. Budget additional memory and benchmark your selected evidence
size on the actual host. The 4B variant is a smaller option (about 3.4 GB).
These are starting candidates, not validated farm-specific models.

Install Ollama on the application server, then run:

```powershell
ollama pull qwen3.5:9b
```

Set in the app environment:

```dotenv
LLM_PROVIDER=ollama
LLM_BASE_URL=http://127.0.0.1:11434
LLM_MODEL=qwen3.5:9b
LLM_API_KEY=
```

The app posts to `/api/chat`. Keep Ollama listening on loopback. Configure
`OLLAMA_NO_CLOUD=1` in the Ollama service environment and restart that service
([Ollama FAQ](https://docs.ollama.com/faq)). App `.env` values do not configure
a separately running Ollama service. Set `OLLAMA_CONTEXT_LENGTH=32768` in that
service to accommodate the app's bounded evidence and conversation; benchmark
memory consumption. Qwen reasoning can use the response budget: the app requests
`think=false` for Ollama so the returned content is a concise answer.

For a separate inference host, put Ollama behind a private HTTPS reverse proxy
that validates a Bearer token, then set `LLM_BASE_URL=https://YOUR_MODEL_HOST`
and `LLM_API_KEY` to that proxy token. Keep port 11434 blocked from public access,
restrict callers to application hosts, and disable prompt/body logging. Ollama's
local API has no built-in authentication; setting an app API key alone does not
secure the server ([authentication](https://docs.ollama.com/api/authentication)).
For an OpenAI-compatible server use the existing `compatible` configuration
above; its base URL includes `/v1`.

Use separate databases and credentials per client. Review real farm questions
against the evidence before enabling chat for clients. No live inference test
has been performed until a model server is installed and configured.
